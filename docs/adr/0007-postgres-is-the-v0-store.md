# Postgres is the v0 store: pgvector + tsvector + River behind one storage port

The Engine's v0 baseline (vector + lexical retrieval over raw history) runs entirely on a single Postgres: pgvector (pinned >= 0.8.0 with iterative scans enabled) for ANN, native tsvector/ts_rank_cd fused via RRF for lexical, and River for durable job state — enqueued in the same transaction as the Ingest write, so the settle barrier (ADR-0006) is a plain query with no cross-system consistency window. All access goes through one narrow internal storage port; retrieval strategies vary above it, the store does not (storage is fixed infrastructure, never a benchmark Subject). Namespaces share one global HNSW index with a `WHERE namespace` filter for now; the committed multi-tenant path is declarative partitioning by Namespace — semantically free because no query ever spans Namespaces — triggered when any Namespace falls below roughly 5% table selectivity.

Rejected: Qdrant (a second stateful service no Report has earned; no relational home for raw history or job state), SQLite + sqlite-vec (brute-force KNN with no ANN index caps self-hosted corpus growth, and the pure-Go path rests on low-maturity wrappers), the hybrid graph-vector class — FalkorDB (SSPL), SurrealDB/Memgraph (BSL), Kuzu (archived Oct 2025), HelixDB (contradictory license claims, pre-1.0) — and true-BM25 Postgres extensions (all AGPL-3.0; tsvector-vs-BM25 is a cheap, attributable Run to make later rather than a day-one dependency).
